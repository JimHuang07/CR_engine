# CR Review Engine v0.1 · 每波防守摘要規格

狀態為設計草案。第一個使用情境是玩家看完一波進攻，能回答「我為了這波防守花了多少聖水？左塔、右塔和主堡各掉多少血？」每波產出一行摘要，可以展開核對出牌明細。第一版接受人工標記的波次與出牌時間。自動分波、最佳解搜尋與完整動畫重建列為後續工作。

## 1. 分析單位與時間

一波由 waveId、防守方、開始 tick、結束 tick 定義。人工在對手發動進攻或我方預先防守前標起點，在最後一次相關塔傷結算後標終點。預先放置且已存在的建築記為起始場面資源。若要把建築費用歸入該波，將起點移到部署前。雙路同時受壓時合為一波，保留各塔明細。同一防守方的波次可相鄰，禁止重疊以免重複計費。

採用半開區間 [a,b)。狀態 S(k) 表示第 k 個 tick 處理任何操作前的局面。先執行 tick k 的操作，再推進到 S(k+1)。起點快照為 S(a)，終點快照為 S(b)。落在 b 的出牌歸下一波。防守單位存活並開始反攻時可以結束該波。片段提前中止或結尾仍有攻擊物飛向塔時，標為「未結算完」，顯示截至當時的結果。

## 2. 兩個核心指標

| 欄位 | 計算方式 |
|---|---|
| 防守用水 | 加總該波防守方成功支付、人工標記用途為 defense 或 mixed 的出牌實付費用。兼具防守與進攻用途的牌整筆計入一次，明細顯示 mixed。純進攻牌標為 offense 並排除。 |
| 各塔掉血 | 對防守方左公主塔、右公主塔及主堡各計算 HP(a) − HP(b)，摧毀後按 0 HP。左右以防守玩家視角命名。 |
| 總塔傷 | 三座塔掉血的總和。涵蓋部隊、建築及法術在期間造成的損血。v0.1 的支援情境假設塔不回血。 |

聖水回復、溢出及波前部署的單位不產生本波新支出。召喚多個單位只算一次出牌。另列「波內總支出」供核對。用途尚未標記時，防守用水顯示待確認，並列已確認小計。塔血缺值顯示未知，總塔傷也標未知。零費防守與零塔傷均為有效結果。兩指標並列呈現，避免零費除法，也保留「多花一費能省多少血」的資訊。

## 3. 輸入與輸出契約

| 資料 | 必填內容 |
|---|---|
| 對局設定 | 對局 ID、規則與卡牌資料版本、雙方牌組及初始順序、塔種類與等級、初始聖水、時間步長、模擬器版本。隨機初始化須保存種子或實際初始化結果。 |
| 出牌紀錄 | 唯一 actionId、tick、同 tick 的順序、玩家、卡牌、落點。波內防守方操作另帶用途。座標沿用上游世界座標，錄影像素與防守視角在顯示層轉換。 |
| 波次 | 波次 ID、邊界、防守方、完整性。可附錄影時間與人工讀取的三座塔起訖 HP。 |
| 摘要 | 對局及波次 ID、來源（模擬／錄影觀測）、時間範圍、防守用水、波內總支出、逐塔掉血、總塔傷、完整性及逐筆計費明細。 |

相同 actionId 的相同輸入只處理一次，內容衝突時回報錯誤。同一波可並排顯示模擬與錄影觀測值，兩組數值各自保留來源。區間內若有其他戰鬥的塔傷，須合併波次或標為混合事件，避免把區間總量解讀為某張卡的因果效果。

## 4. 上游模擬器整合

參考版本為 [Jason-XII/clash-royale-simulator @ 82bcbf3](https://github.com/Jason-XII/clash-royale-simulator/tree/82bcbf3088102318125fc0193f0e5bc38e7886b2)。Python adapter 管理 BattleState，輸出 JSON 給 review 層。初版以獨立 checkout 指定依賴，直接沿用該版支援的卡牌資料。若要把上游原始碼納入本 repo，先確認授權。

1. 從已知開局重播雙方完整出牌序列，讓波前場上單位、生命、手牌和冷卻自然延續。只有片段且無法還原起始狀態時，可產生錄影觀測摘要，模擬欄標為缺少起始狀態。
2. 以整數 tick 排序與調度。建議起始設定為每秒 20 tick，記錄實際 dt，並用實戰校準。時間落在兩個 tick 間的操作排入下一個 tick。同 tick 依輸入順序執行。
3. 到出牌 tick 才呼叫 deploy_card(player_id, card_name, position, delay=0)。上游會在呼叫時支付並循環手牌，delay 控制之後的生成時間。提前排入上游會使計費和手牌時序偏移。
4. 成功時立即在 step(dt) 前讀取支付前後聖水差，保存實付費用。回傳 False 時保存失敗原因（若可取得），費用為零。重播已知實戰出牌卻遭拒絕時，將該波標為重播不一致。
5. 在兩個邊界讀取各塔 HP，保留穩定塔 ID 與毀塔事件。只在已確認摧毀時補零。提早結束對局時，以實際終局狀態結算並記錄有效終點。

## 5. 呈現範例與比較

以下為虛構驗收資料。原始方案中，加農砲花 3 費，骷髏兵花 1 費，左塔從 3000 降到 2680，其餘塔血維持原值。

| 波次／方案 | 防守用水 | 左塔掉血 | 右塔掉血 | 主堡掉血 | 總塔傷 |
|---|---:|---:|---:|---:|---:|
| 第 1 波・原始 | 4 | 320 | 0 | 0 | 320 |
| 第 1 波・替代落點 | 4 | 0 | 0 | 0 | 0 |

摘要可寫「相同 4 費，替代落點少掉 320 HP」。比較時固定起始場面、對手出牌、版本及結算終點。若任一方案未結算完，顯示部分結果。第一版交付單方案摘要即可，既有 rankDefenses 的加權分數不作為這張摘要的驗收條件。

## 6. 驗收

| 測試局面 | 預期結果 |
|---|---|
| 範例中的兩筆成功出牌，期間自然回復 1 費 | 防守支出 4、總塔傷 320。 |
| 骷髏兵生成多隻，其中一隻存活到下一波 | 第一波計一次 1 費，下一波沒有新部署就計 0。 |
| 波前的加農砲獨自完成防守 | 本波用水 0，可在起始場面查到既有建築。 |
| 同波花 3 費防守、另花 4 費進攻 | 防守用水 3，波內總支出 7。 |
| 部署被拒絕，下一 tick 成功 | 僅成功操作扣費，兩筆明細均可查。 |
| 兩個相鄰波次，第二波起點出牌 | 該次費用只歸第二波。 |
| 左塔剩 100 HP 後被毀，右塔同期掉 70 HP | 左塔 100、右塔 70、主堡 0，合計 170。 |
| 同一設定與事件重跑兩次 | 每波實付明細與三塔邊界 HP 完全一致。 |
| 實戰對照 | 至少用一段人工標記的野豬對加農砲錄影，逐筆核對費用與三塔起訖 HP；記錄差異與首次偏離時間。 |

首個可交付版本為「一段對局事件紀錄 → 一次可重現的模擬 → 一張逐波摘要表」。錄影疊圖與落點搜尋可以沿用同一份波次及事件格式。
